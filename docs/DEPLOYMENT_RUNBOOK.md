# 🎷 Jazz Portfolio — Deployment Runbook

This guide details the step-by-step instructions for provisioning, configuring, and deploying the Jazz Portfolio application stack to AWS.

---

## Architecture Overview
- **Next.js Frontend:** Deployed to AWS Amplify (managed hosting & CDN).
- **NestJS REST API:** Run inside a Docker container on AWS EC2 (t4g.micro, ARM).
- **Database:** AWS RDS PostgreSQL (db.t4g.micro, gp3).
- **Media & Tracks:** Stored in AWS S3, served through an AWS CloudFront CDN.

---

## Phase 1: Storage & Media CDN (S3 + CloudFront)

### 1. Create S3 Bucket
1. Open the Amazon S3 console and click **Create bucket**.
2. **Bucket name:** `jazz-portfolio-media` (or a unique variant).
3. **Object Ownership:** *ACLs disabled (recommended)*.
4. **Block Public Access settings:** Keep *Block all public access* turned ON (we will serve objects exclusively through CloudFront).
5. Click **Create bucket**.

### 2. Configure S3 CORS Policy
In the S3 bucket's **Permissions** tab, add the following CORS configuration to allow direct browser uploads via presigned URLs:
```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["PUT", "GET", "POST", "HEAD"],
    "AllowedOrigins": ["*"],
    "ExposeHeaders": ["ETag"]
  }
]
```
*(In production, restrict `AllowedOrigins` to your production frontend domain).*

### 3. Create CloudFront Distribution
1. Open the AWS CloudFront console and click **Create distribution**.
2. **Origin domain:** Select your S3 bucket.
3. **Origin access:** Choose **Origin access control settings (OAC)**, click **Create control setting**, and accept defaults.
4. **Viewer protocol policy:** *Redirect HTTP to HTTPS*.
5. Click **Create distribution**.
6. Once created, copy the S3 Bucket Policy generated by CloudFront, open your S3 bucket's **Permissions** tab, and paste it into the **Bucket policy** field to grant CloudFront access.

## Phase 2: Database Provisioning (AWS RDS)

1. Open the Amazon RDS console and click **Create database**.
2. **Engine options:** PostgreSQL 16.x.
3. **Templates:** *Free Tier* (uses `db.t4g.micro`, 20GB gp3 storage).
4. **Settings:**
   - **DB instance identifier:** `jazz-portfolio-db`
   - **Master username:** `postgres`
   - **Master password:** *[Select a strong password]*
5. **Connectivity:**
   - **Public access:** No.
   - Select or create a VPC Security Group that allows inbound TCP traffic on port `5432` from your EC2 security group.
6. Click **Create database**.

---

## Phase 3: Host Configuration (AWS EC2)

1. Launch a `t4g.micro` (ARM64) instance using the **Amazon Linux 2023 AMI**.
2. Configure a Security Group allowing:
   - Port `22` (SSH) from your IP or GitHub Action runner IPs.
   - Port `3001` (NestJS REST API) from everywhere or AWS Amplify CIDR ranges.
3. SSH into the EC2 instance and install Docker:
   ```bash
   sudo dnf update -y
   sudo dnf install docker -y
   sudo systemctl start docker
   sudo systemctl enable docker
   sudo usermod -aG docker ec2-user
   ```
4. Install Docker Compose:
   ```bash
   sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
   sudo chmod +x /usr/local/bin/docker-compose
   ```
5. Clone the repository and configure host files:
   ```bash
   mkdir ~/personal && cd ~/personal
   git clone <your-repository-url> .
   ```

---

## Phase 4: Frontend Hosting (AWS Amplify)

1. Open the AWS Amplify console and click **Create new app**.
2. Select **GitHub** as the source, authorize AWS, and select your repository and `main` branch.
3. **Amplify Build Settings:** Amplify will auto-detect Next.js. Update the build configuration to specify the `apps/web` root:
   ```yaml
   version: 1
   applications:
     - appRoot: apps/web
       frontend:
         phases:
           preBuild:
             commands:
               - corepack enable
               - pnpm install
           build:
             commands:
               - pnpm run build
         artifacts:
           baseDirectory: .next
           files:
             - '**/*'
   ```
4. **Environment Variables:** In Amplify App Settings, configure:
   - `NEXT_PUBLIC_API_URL`: `https://your-ec2-domain:3001/api`
   - `API_INTERNAL_URL` (optional): a private API base URL reachable from the Next.js runtime;
     omit it when Amplify cannot reach the API privately
5. Click **Save and deploy**.

---

## Phase 5: CI/CD Secrets Setup (GitHub)

In your GitHub Repository, navigate to **Settings > Secrets and variables > Actions** and add the following secrets:
- `AWS_EC2_HOST`: The public DNS or IP address of your EC2 instance.
- `AWS_EC2_USERNAME`: `ec2-user`
- `AWS_EC2_SSH_KEY`: The contents of your private `.pem` key file used for SSH access.

---

## Routine Operations & Redeployments
- Pushing backend changes (in `apps/api` or `packages/*`) to `main` automatically triggers the **Deploy Backend API** workflow, SSHing into EC2, pulling the changes, rebuilding Docker, and executing migrations.
- Pushing frontend changes to `main` triggers AWS Amplify's automated build and deployment webhook.
